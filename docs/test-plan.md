## 1. 如何使用

2026-11-12 新增三层配置执行记录：[Provider 验收](test-results-2026-11-12-providers.md)。PROV-01～14 的领域/协议/浏览器/真实原生范围分别登记；Gemini Chat 网关双轮及原生文件工具通过，Google 直连、普通 Cursor Agent 自定义 Provider 入口、真实手机及其他转换方向仍待验证或未支持。配置请求去重、Provider 编辑往返及一键绑定默认值原子保存作为新增回归点。

1. 选定模块及用例 ID；首次可按第 5 节的冒烟顺序执行。
2. 按第 3 节建立隔离环境，记录版本、数据目录、工作位置、绑定修订及测试设备。
3. 按用例“操作”和“预期”执行，在第 9 节模板中逐项记录实际结果和证据。通用 harness 用例必须按每一种 harness 分别实例化。
4. 失败登记缺陷；缺 CLI、登录、设备或 Electron 环境条件时登记“阻塞”；缺功能登记“未实现”；原生协议确实没有能力时登记“原生不支持”。
5. 修复后重测原用例，并执行第 8 节对应回归组。历史通过记录不能直接填作本轮结果。

### 1.1 用例与结果规则

用例 ID 固定，后续新增编号、不重排旧号。原生实例用 `H-<harnessId>-<编号>`，例如 `H-codex-03`、`H-pi-03`；内置主 agent 使用 `H-kodo-03`。一次运行标识建议为 `YYYYMMDD-HHMM-短名称`。

| 状态 | 记录规则 |
| --- | --- |
| 未执行 | 尚未按指定环境与版本执行，不推断结果 |
| 通过 | 操作及所有预期满足，有本轮证据 |
| 失败 | 实际结果不符合预期，关联缺陷 ID |
| 阻塞 | 缺少外部前置条件，写明具体条件和解除方式 |
| 未实现 | 产品缺少实现路径，不能归因于环境 |
| 原生不支持 | 原生协议/版本不提供能力，记录来源与版本；同时测试界面是否如实表达 |
| 不适用 | 用例确实不适用于此对象，写明原因；不能代替失败或未实现 |

“原生不支持”可以使相应的**边界展示用例**通过，但不代表该原生能力通过。协议 peer、真实模型、浏览器视口、真实手机、Electron 必须分别记录。协议通过不能升级成真实接入通过。

| 优先级 | 含义 |
| --- | --- |
| P0 | 不应重复执行、丢失已提交状态、越过管理范围、停止后自动重启或错误确认成功；关键恢复与直接聊天路径 |
| P1 | 主要产品功能、原生能力真实性、配置隔离、历史/搜索、双端一致性 |
| P2 | 长期维护、显示细节、可访问性、工程与补充兼容性 |

表内方法缩写：`A`＝领域/存储/进程自动化；`P`＝隔离合成协议 peer；`N`＝真实原生 harness；`B`＝浏览器；`E`＝真实 Electron；`M`＝真实手机。需要多种方法时分别保留结果。

## 3. 前置环境、数据和证据

### 3.1 环境登记

每轮记录 Git HEAD 和工作区变更摘要、操作系统、Node/npm、SQLite schema、浏览器/Electron、CLI/SDK 版本与启动路径。未提交工作区同样需要记录，不能只写 HEAD。初始工程基线为 Node `>=24.13.0`，包管理器按根 `package.json` 的 `packageManager`。

使用独立 `KODO_DATA_DIR`、空闲端口及临时项目目录，不连接用户日常 Host。数据准备约定：

- `项目 A`、`项目 B`，各有单独工作目录；另备非 Git 目录、带空格/中文路径和一个小型测试 Git 仓库。
- 两个 Kodo 主对话、同项目多个 harness、跨项目目标及未归属会话。需要真实聊天的项目指向临时工作位置。
- 两个绑定修订、两个客户端；凭据轮换只使用可删除的合成凭据，真实模型使用已有有效登录/授权。
- 历史数据包括中文、英文、混合文本、工具输出和至少 1,000 条事件。大历史、时间推进和异常路径用隔离 fixture，明确标为合成测试，不写入真实原生历史。
- 分页/GC、异常退出、连接替换等测试使用可丢弃数据库。预先保存基线；不在日常运行中的数据库上做故障注入或修改系统时钟。

PowerShell 启动示例，先确认示例端口未占用：

```powershell
npm ci
npm run build
$qaRunId = Get-Date -Format 'yyyyMMdd-HHmmss'
$env:KODO_DATA_DIR = Join-Path (Get-Location) ".local/qa/$qaRunId"
$env:KODO_HOST_PORT = '4327'
$env:KODO_HOST_URL = 'http://127.0.0.1:4327'
npm run start:host
```

浏览器访问该 Host；测试 Electron 时在其启动终端设置相同的三个环境变量，核对实际连接端口与数据目录。上述变量只作用于当前终端；测试结束后恢复该终端原有值，或关闭测试终端。

现有 Playwright 配置独立使用 `4319` 和 `.local/ui-tests/<时间戳>`，不复用已有服务；`verify:live-ui` 当前使用 `4323`。运行前检查冲突，不能只改上例端口就认为所有脚本已改用该端口。

原生脚本各自建立 `.local/verification` 下的数据目录，部分脚本使用固定子目录，且以当前仓库为工作位置；不能假定它们统一服从 `KODO_DATA_DIR` 或提供临时 cwd 参数。先阅读对应 `scripts/verify-*.mjs`，只运行无文件修改的最小提示；需要工具改文件时在隔离项目按用例操作。脚本超时只说明该验证未完成，不能据此判定 harness 的原生回合有相同超时限制。

### 3.3 证据及清理

每个结果至少记录用例 ID、环境、步骤、预期、实际、时间和证据位置。递送/恢复用例附产品与原生 session/run ID、request/command ID、事件 sequence、watch cursor/generation、数据库重开前后状态。UI 用例附截图、console 和必要的网络记录；真实接入附脱敏原生回执。

原始材料放 `.local/qa/<运行ID>/` 或已有 `.local/verification/`、`output/playwright/`；提交的报告只留脱敏摘要与必要引用。不记录凭据、配对码或 token 原文。结束时先暂停测试托管、核对原生运行及未知命令，再停止测试 Host；清理合成 keyring 条目和专用 worktree，保留未解决缺陷的证据。不把关闭 UI 当作清理任务已结束。

| ID | 优先级/方法 | 前置与操作 | 预期与检查点 |

### 4.4 会话中心与直接聊天（SES）

| ID | 优先级/方法 | 前置与操作 | 预期与检查点 |
| --- | --- | --- | --- |
| SES-01 | P0 / A+B | 逐一创建十种 harness 草稿及 Kodo 主对话，不发送 | 均有独立入口；没有虚构原生 ID/运行/回复；缺安装给具体说明 |

### 4.5 每种 harness 的通用契约（H）

将下表分别用于 `pi`、`codex`、`claude-code`、`deepseek-harness`、`zcode`、`opencode`、`gemini`、`cursor`、`kimi-code`、`grok-build`，另用于 Kodo。用例编号以 `H-<id>-NN` 记录，不合并成一条“全部适配器通过”。

### 4.6 六工具、授权与自动控制（CTL）

前置：项目 A/B、两个 Kodo 主对话、一个可完成真实回合的目标；涉及事件竞态先用受控 peer，再做至少一条真实闭环。

| ID | 优先级/方法 | 前置与操作 | 预期与检查点 |
| --- | --- | --- | --- |
| CTL-01 | P1 / A+N | 调用 `harness_list/open/read/send/watch/stop`，与 UI 相同动作比较 | 走同一 Host API/事务；过滤、工作位置、异步回执与真实能力一致；无额外隐式写通道 |
| CTL-02 | P0 / A+B | 全局 Kodo 关联 A/B；项目 Kodo 只关联 A，尝试选择 B | 全局仅管理用户选定范围；项目范围受约束；目标保留原项目/原生身份；关联卡片不复制会话 |
| CTL-03 | P0 / A+B | 两个主对话同时申请同一目标自动控制，另加多个观察者 | 仅一个自动控制者；多个观察者可共存；冲突明确，无双重自动输入 |
| CTL-04 | P0 / A+B | 转交控制权时保留旧 generation 的待办/迟到事件 | 转交原子提交；旧待办失效；新控制者唯一；不重启已有原生回合 |
| CTL-05 | P0 / A+B+N | 托管目标有自动排队消息时，用户从桌面或手机直接发送 | 先暂停/递增 generation、撤销未发自动输入，再按能力发送/排队/steer；已发送不声称撤回 |
| CTL-06 | P0 / A+N | 分别使用仅观察、通知、自动继续；观察实际模型调用计数 | 前两种零模型调用；自动继续由持久事件唤醒；不是轮询模型或默认固定工作流 |
| CTL-07 | P0 / A+N | 先 send、目标快速完成后才注册 watch；重复注册同一观察 | 补发对应完成状态/游标；仅一次有效 wake；一次性已消费事件不因重注册而再次执行 |
| CTL-08 | P0 / A+B+N | 分别执行取消本轮、暂停托管、停止并暂停；之后到达目标完成事件 | 三种效果区分；停止并暂停先持久暂停，再请求取消；迟到事件不能恢复自动续聊 |
| CTL-09 | P0 / A+B | 停止 Kodo 主对话；其目标仍在运行并随后完成 | Kodo 对外自动控制同时暂停；后续事件不重新启动它；不误停其他主对话管理的独立目标 |
| CTL-10 | P1 / A+B | 设置仅允许创建；改为创建并自动继续；分别创建新目标后撤销授权 | 前者不授自动控制；后者只控制此后新建目标并继承限制；不接管已有/已暂停目标；撤销不暗改已有关系 |
| CTL-11 | P0 / A | 在 scope 不合法时创建托管草稿，检查事务回滚 | 草稿、请求映射、关系一并回滚；无幽灵会话/事件或执行 |
| CTL-12 | P1 / A+B | 为同一主对话设置观察和继续目标；触发次数/截止时间/连续失败上限 | 限制由 Host 执行；达到阈值暂停并入收件箱；轮询、审批等待、未知断线不计已确认失败 |
| CTL-13 | P1 / A+B | 尝试对另一主对话自动续聊；批量停止仅列出自己控制目标 | 首轮不形成主对话相互自动唤醒；批量范围明确；逐项报告未知/不支持，不显示虚假全成功 |

## 5. 推荐执行批次

一次可以只完成一个模块。批次编号用于组织，不改变原用例 ID；耗时及模型费用以实测记录，不预设“全部一天完成”。

| 批次 | 执行范围 | 完成本批需留下的材料 |
| --- | --- | --- |
| S0：无模型冒烟 | ENV-01/02，ID-01/05，SES-01/03，REL-15，UI-02，OPS-05 | 工程退出码、Host 健康、十种入口 + Kodo 截图、console |
| S1：领域与可靠性 | CTL、REL、INB-02/03、CFG、COST、OPS-01/02 | 自动化报告及关键事务/命令/游标证据；缺少自动化的项单列待测 |
| S2：原生逐种验收 | 每种 H-01～14、对应 ADP，优先 H-03/07/09 | 每 harness 独立记录，不用一个总通过替代 |
| S3：真实托管闭环 | CTL-01/05/06/07/08/09、COST-01，先 Kodo→Codex，再扩展目标 | 六工具轨迹、唯一原生发送、持久 wake、暂停后迟到事件不续聊 |
| S4：工作台功能 | PRJ、SES、INB、SRCH、OUT、UI | 按模块功能结果、来源链接和边界截图 |
| S5：桌面与手机 | DESK 全部；MOB 全部 | Electron 生命周期证据与实际手机 HTTPS/休眠重连证据分别提供 |
| S6：长时与交付 | OPS、规模测试、未通过项重测、关键回归 | 数据增长/维护记录、剩余限制及完整状态矩阵 |

最小真实冒烟链路：在隔离项目用某个 harness 发一轮→检查真实 ID/回复→第二轮→按能力恢复→查看历史或不支持提示→执行停止/暂停并核对真实结果。对 Kodo 额外执行一条真实管理闭环。该链路必须对十种分别登记，不因前四种可用而宣布首轮完成。
