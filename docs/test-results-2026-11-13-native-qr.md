# 原生应用内扫码实现与验收范围

## 已实现

- Android：私有扫码 Activity、后置相机预览、QR-only 本机识别、补光/取消、权限申请与设置恢复、前后台相机释放恢复、旋转后重建、一次结果回传。无相机仍可安装和手动配对。
- iOS：VisionKit 扫描页、能力检测、相机权限说明和请求、拒绝/受限/不可用提示、取消/重试、前后台启停、一次结果回调。
- 二维码解析：只接受 HTTPS Host 或 `/h/<64 位小写 hex>/` Relay 路径，加 `#pair=<32 位 hex>`。拒绝 userinfo、查询参数、重复 fragment、其他路径、路径穿越和超长输入。保留完整 Host 路由，统一邀请码大小写。
- 识别后停止相机，展示连接地址并确认，随后复用已有原生配对 API 与凭据库；不自动访问任意二维码网址，不改变服务器协议。

## 本机验证

- Android JDK 17 / SDK 36：`testDebugUnitTest lintDebug assembleDebug` 通过，7 项单测全部通过，其中 3 项新增扫码用例。
- 新增测试包含实际 QR 像素图的 ZXing 编码/解码，以及合法 Relay、自建 HTTPS 地址和 18 种错误输入的解析检查。
- 合并 Manifest 已确认相机权限、可选相机硬件、扫码 Activity 不对外导出。
- 安装包：`apps/android/app/build/outputs/apk/debug/app-debug.apk`，开发签名。
- iOS 添加 XCTest 解析用例；当前 Windows 没有 Xcode，未执行 iOS 构建或 XCTest。
- `adb devices` 当前没有设备；没有把 JVM 解码测试表述为真实相机验收。

## 真机验收步骤（待执行）

1. 桌面生成新二维码；手机 App 点击扫码、授权、扫描并确认，预期保存连接并出现会话列表。
2. 首次拒绝权限，再次点击/从设置恢复；预期有明确提示，可重试或手动输入。iOS 受限/不支持设备显示手动入口。
3. 扫描普通网址、缺少邀请码或无效二维码：预期提示错误，不打开浏览器、不发送配对请求；可重扫。
4. 使用已消费或过期邀请：预期沿用 Host 的无效/过期提示，重新生成后可连接。
5. 扫描中取消、锁屏、切后台再返回、旋转设备：预期相机释放/恢复，不重复消费邀请。
6. 连续对准同一码、重复点击连接：预期每轮扫描只返回一次，配对过程中按钮禁用。
7. Android 补光开关、iPad/横屏、大字号、VoiceOver/TalkBack：检查操作可达性和地址可读性。

本次没有修改 Relay 服务端，之前公网配对/撤销/升级重连的证据仍见 `docs/mobile-relay.md`。完整 UI 回归的既有失败未在本次重跑或声明修复。
