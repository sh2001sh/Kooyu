# Kodo 主对话定位

日期：2026-11-12。状态：定位设计，待评审。本文件定义 Kodo 主对话**做什么、在哪里做、做到哪一步为止**。会话归属与显示见 [会话模型](session-model.md)，消息递送与监控机制见 [总体设计 §4–5](design.md#tools)，已实现部分见 [实现状态](implementation-status.md)。

## 1. 一句话定位

**Kodo 是用户在多个 coding harness 之上的“工作负责人”：它管理会话、跟进目标、编排 harness 完成任务，但自己不替代任何 harness，也不是使用它们的必经入口。**

用户可以完全不打开 Kodo，直接与 10 种 harness 对话；当用户需要“有人盯着、有人汇总、有人拆分和续接”时，才把工作交给 Kodo。

## 2. 四种角色

同一个 Kodo 主对话承担四种角色。它们不是四种会话类型，而是 Kodo 按用户请求在一段对话中自然切换的工作方式；共享同一套工具和授权规则。

| 角色 | 用户会这样说 | Kodo 做什么 | 主要工具 | 是否会写入其他会话 |
| --- | --- | --- | --- | --- |
| **A. 会话管理员** | “我现在有哪些会话在跑？”“把昨天那几个 Codex 会话归档”“新建一个 Claude 会话看看这个 bug” | 查询、汇总、创建、改名、归档、移动归属、停止 | `harness_list` `harness_read` `harness_open` `harness_stop` + 会话整理操作 | 只有创建、停止、整理；不代替用户发消息 |
| **B. 进展汇报员** | “汇报一下各项目进展”“登录改造做到哪了？” | 按项目/目标读取会话最新状态与结果，生成简短报告，标出卡住、失败、等待输入的会话 | `harness_list` `harness_read` | 否（只读） |
| **C. 目标监督者** | “盯着这个会话，直到登录功能真正做完”“完成后叫我” | 建立 watch；会话停下时被唤醒，分析目标与当前结果，决定继续发送、核验、请求用户输入或结束 | `harness_watch` `harness_read` `harness_send` + 基础文件/命令工具 | 是，仅限用户授权“自动继续”的目标 |
| **D. 任务编排者** | “用 Codex 实现这个功能，让 Claude 审查，最后跑一下测试” | 拆分任务，选择 harness，创建/复用会话并发送，用 watch 串联，交接上下文，核验结果 | 全部产品工具 + 基础工具 | 是，限当前主对话授权范围内创建或接管的会话 |

角色 A、B 不需要模型持续运行，回答即结束；角色 C、D 是长期目标，依靠事件唤醒持续推进。

### 2.1 角色边界

- **A 会话管理员**不替用户在某个会话里继续对话；“帮我回复这个会话”属于 C/D，需要控制授权。
- **B 汇报员**只读取摘要和结果，不把目标会话的长输出整段复制进主对话；需要细节时引用并跳转。
- **C 监督者**判断的是“用户目标是否完成”，不是“原生 turn 是否结束”。原生 turn completed 只是一次唤醒的理由。
- **D 编排者**不引入固定流程（实现→审查→验收），也不建任务板或子 agent 层级。拆分方式由模型按任务决定，宿主只执行工具调用并递送事件。

## 3. 两种范围

范围决定 Kodo **能管理哪些会话**，与它当前**在哪个目录里工作**分开。

| | 全局主对话 | 项目主对话 |
| --- | --- | --- |
| 位置 | 顶层“主对话” | 项目内“主对话”分组 |
| 能管理 | 用户选定的任意项目、任意 harness 会话，以及未归属会话 | 仅本项目会话 |
| 典型用途 | 跨项目管理与汇报（A、B），跨项目监督（C） | 项目内编排（D），项目内监督（C） |
| 工作目录 | 默认无；需要读写文件时从**选定目标**解析 host/目录，不继承 UI 当前打开的项目 | 项目的工作位置；可在项目多个 workspace/worktree 间选择 |
| 新建会话归属 | 由 Kodo 明确指定项目，不猜测 | 本项目 |
| 费用归属 | 单列为“全局 Kodo 管理费用” | 计入本项目 |

规则：

1. 全局主对话可以选一个工作目录作为默认文件工作位置，但**仍保持全局范围**，不因目录而变成项目主对话。
2. 范围在创建时确定，不静默扩大。项目任务要扩展到跨项目时，新建全局主对话并交接选定会话。
3. 全局与项目主对话平级，不存在“总管管理子总管”。主对话不自动续聊其他主对话，避免相互唤醒。

### 3.1 推荐用法

- **全局主对话 = 跨项目经理**：日常“看看都在干什么”“哪些卡住了”“把 A 项目的修复盯到完成”。一般只需一到两个，按长期目标建。
- **项目主对话 = 项目执行负责人**：在项目里说“把登录改造做完”，由它编排 Codex、Claude 等完成。按目标建多个，例如“登录改造”“发布准备”。

## 4. 授权模型

Kodo 能做什么，由“读 / 建 / 写”三级授权决定，而不是由它在哪个范围。

| 级别 | 包含操作 | 授权方式 |
| --- | --- | --- |
| 读 | 列表、读取历史与状态、汇报 | 范围内默认允许，无需逐次确认 |
| 建 | 新建会话、整理归属、归档、观察（observe/notify） | 首次在对话中展示目标与范围并确认；项目可预先授予“仅授权创建” |
| 写 | 向会话发送消息、自动续聊（continue）、停止他人运行 | 必须对**具体目标**显式授权；项目可预先授予“创建并自动继续”，只覆盖 Kodo 之后**新建**的会话 |

不变的约束（沿用已实现机制）：

- 同一会话同时只有一个自动续聊控制者；用户直接在该会话发消息会暂停自动续聊，需显式重新启用。
- 原生审批和用户输入请求不会因托管被自动确认，进入待处理收件箱由用户处理。
- 结束时间、最大续聊次数、连续失败阈值、预算达到上限即暂停，并进入收件箱。
- 原生 turn 完成、超时或断线都不能被当作“目标完成”。

## 5. 工作循环

### 5.1 监督循环（角色 C）

```text
用户：“盯着 #登录改造 这个 Codex 会话，直到登录和测试都通过”
  ↓ Kodo 确认目标、会话与限制 → harness_watch(mode=continue, goal=…)
  ↓ Kodo 结束本轮，不空转
Codex 回合结束 → Host 持久唤醒 Kodo
  ↓ Kodo harness_read 读取结果；必要时自己读文件/跑测试核验
  ├─ 未完成：harness_send 下一步指令，继续等待
  ├─ 需要用户：说明原因，暂停续聊，进入收件箱
  └─ 已完成：撤销 watch，向用户汇报证据（diff、测试结果）
```

关键点：**“自动分析项目然后让其继续”由 Kodo 在每次唤醒时完成**——它读取会话结果，结合目标与仓库实际状态判断下一步，而不是把“继续”机械地发给 harness。

### 5.2 编排循环（角色 D）

```text
用户在项目主对话：“实现导出 CSV，Codex 写、Claude 审查”
  ↓ Kodo 拆分：实现 → 审查 → 修复 → 验证
  ↓ harness_open(Codex, 本项目 worktree) + harness_send + harness_watch
Codex 完成 → 唤醒 → Kodo 核验
  ↓ harness_handoff → Claude 会话（携带 diff 摘要与来源链接）
Claude 审查完成 → 唤醒 → Kodo 汇总意见 → 回发 Codex 修复 → …
  ↓ 最终 Kodo 自己跑测试/读 diff → 向用户报告
```

编排时 Kodo 可并行多个执行会话，但不默认让多个实现会话同时修改同一工作区；需要并行写入时为每个会话选择独立 worktree。

### 5.3 管理与汇报（角色 A、B）

一次性问答，不建立 watch，不唤醒：

- “汇报进展” → 按项目分组列出：运行中 / 等待输入 / 失败 / 最近完成，每项一句状态 + 跳转链接。
- “清理一下” → 列出建议（长期空闲、已完成）并等待确认，再归档或停止。

## 6. 界面呈现

- **主对话正文**：用户目标、Kodo 回复、工具调用折叠卡、目标会话的引用卡片（项目 / harness / 状态 / 最近事件 / 跳转）。不内嵌子会话副本。
- **顶部“管理中的会话 N”**：展开侧栏查看所有关系及模式（观察 / 通知 / 自动继续）、限制与暂停原因。
- **被管理会话**：顶部显示“由〈主对话名〉管理”，Kodo 发出的消息标记“由主对话发送”。
- **入口**：
  - 顶层“新建主对话” → 全局。
  - 项目内“新建主对话” → 项目范围。
  - 任意会话的“交给主对话” → 选择范围兼容的主对话或新建，并设定模式。
- **新建草稿**：选择 Kodo 时，项目选择器的语义是“范围”，工作目录选择器的语义是“默认文件工作位置”，两者分开显示。

## 7. 不做什么

- 不是所有对话的必经入口：直接对话不经过 Kodo，不消耗其模型调用。
- 不自动接管：未归属或已有会话不会因为存在 Kodo 而被管理；Kodo 不自动扫描全库并开始续聊。
- 不做定时轮询或模型心跳；无事件时不运行。
- 不建任务板、任务树、固定审查流程或多层 agent。
- 不根据关键词判定任务完成；完成由 Kodo 结合证据判断，用户可随时接管或否决。

## 9. 验收场景

1. 不创建任何主对话，10 种 harness 均可直接使用。
2. 全局主对话一句“汇报进展”，列出两个项目共 5 个会话的状态，无写入、无 watch。
3. 全局主对话监督项目 A 的 Codex 会话直到测试通过，期间用户在该会话手动发言后，自动续聊暂停且不再自动发送。
4. 项目主对话编排 Codex 实现 + Claude 审查，两者留在本项目，费用计入本项目；Kodo 自身费用单列。
5. 全局主对话选择了工作目录后仍显示为全局，不出现在项目列表中。
6. Kodo 请求停止或向未授权会话发送消息时被拒绝，并在对话中请求用户确认。
