# Provider 与旧 Profile 配置入口收敛

> 历史报告：此页记录当时保留旧 API 与编辑入口的过渡实现。当前未上线产品已彻底移除该入口，见 [最新移除记录](test-results-2026-11-12-binding-only.md)。下述测试结论只适用于当时的代码。

日期：2026-11-12。对应测试大纲 PROV-15。

## 实现

- Provider 保存接口、地址和凭据；模型库保存模型参数与来源；Harness 绑定选择两者及默认思考设置。绑定在 Host 中生成不可变的 Profile 修订，供会话和默认值引用。新配置只从这条路径创建。
- 配置页不再提供“添加 profile”；草稿的模型菜单不再快速创建扁平 Profile 或写入另一份 Provider ID/API key。菜单仍可选择现有绑定、旧版配置及原生模型。
- 已有扁平 Profile 在存在时显示于折叠的“旧版模型配置”，可编辑、设默认和继续用于新会话。旧会话保留原修订。旧 Profile 自动导入的 Provider 是独立副本；界面明确提示两者编辑不互相同步。
- Host 的旧 `/profiles` API 和持久数据未删除，以保持旧客户端、会话与修订兼容。直接调用该 API 仍可创建旧格式，统一入口目前属于产品界面约束。
