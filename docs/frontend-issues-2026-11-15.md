> 历史基线：本文记录重构前发现的问题，表内状态不代表最新实现。移动端导航、模型入口、目录选择、输入框、队列、询问/审批及项目创建的后续实现与验证见 [移动端重构实现记录](mobile-restructure-implementation-2026-11-15.md)。其余条目仍需分别核查，不能将旧清单作为当前完整缺口清单。

日期：2026-11-15。本文只记录现存问题、证据、影响和验收缺口，不提出前端视觉或页面设计方案。Android 依据本轮 BlueStacks Android 13 实测截图与源码；iOS 仅作静态入口核查，不能视为已运行验证。

证据目录：`output/playwright/desktop-android-refresh-20261115-143756/`。桌面 93 张、Android 38 张图片的通过结论仅适用于已遍历状态，不等同于所有功能已接入。截图使用隔离数据且未执行真实模型推理，不能证明真实长对话、流式性能及全部原生交互都已验收。

## P1：移动端交互与状态问题

| 编号 | 问题 | 证据与影响 |
| --- | --- | --- |
| M08 | 新建对话配置负担过重 | `04-new-conversation.png` 中标题、项目、目录、引擎、类型、来源、权限排在首条消息之前；开始任务需要先理解配置体系 |
| M09 | 配置术语及继承关系难以理解 | 来源、绑定、模型、项目默认、电脑默认和原生默认同时出现；最终生效配置和覆盖来源不清晰 |
| M10 | 会话详情混合业务设置与排障记录 | `16-session-settings.png` 将基础配置、事件、指令队列和文件并列；常用模型操作进入深层设置 |
| M11 | 会话内导航上下文中断 | 窄屏会话隐藏底部导航；本轮通知测试必须先返回列表才能进入设置，跨区域操作增加往返 |
| M12 | 状态信息在两端含义不一致 | 同一测试会话桌面显示尚未启动、原生未连接、自动继续未启用，Android 主要显示 Kooyu·空闲；`Models.kt` 只按 runState 生成粗粒度标签 |
| M13 | 未知结果核对缺少足够上下文 | 通用提示为“此电脑有操作结果待核对”，操作为“核对后清除”；只有部分写操作可自动查回执，用户不容易判断应核对什么及是否安全重试 |
| M14 | 草稿与附件没有完整持久保存机制 | 对话草稿为 `rememberSaveable(state.selected)`，附件为 `remember(state.selected)`，未见按 Host/会话保存的持久草稿仓库。跨会话/销毁/进程重建的连续性尚不完整；此项不是已复现的全部丢失场景 |
| M15 | 排障数据直接面向普通用户 | 事件详情直接显示 JSON payload，队列直接显示原始状态值，部分卡片显示底层错误；数据可见但业务含义不清楚 |
| M16 | 权限模式由手机硬编码 | `permissionChoices()` 按引擎 ID 维护枚举，可能与 Host 和原生协议支持范围漂移；不能据此断言每个现有选项都错误 |
| M17 | 在线与可执行状态未充分区分 | Host 可连接、引擎已安装、原生账号已登录、会话已连接和模型配置可用是不同事实，现有页面容易混为就绪 |

| V06 | Android 目前只跟随系统主题，桌面支持独立偏好 | 跨端外观设置行为不一致；“宿主通用设置”也不能等同于本机外观设置 |

## 桌面端问题

1. 工作中心位于设置内，却承载计划、通知、运行等日常业务，配置区域和工作区域职责混杂。
2. 同一任务的信息分散在会话、目标、成果、验证、待处理和运行记录中，需要用户自行串联。
3. 引擎、来源、模型、绑定、权限、默认配置的多层关系复杂；保存成功不等于真实可执行。
4. 桌面有较完整的任务上下文，手机信息明显减少；用户换设备后需要重新理解状态及入口。

## 功能文档与验收口径

`mobile-feature-parity.md` 中将模型配置、托管、队列编辑等整体记为已实现的口径过宽，需要区分“服务存在”“组件有源码”“入口可达”“流程闭环”“实机验证”。本文不覆盖或删除历史记录，以保留当时验收事实。

以下事项仍不能从现有空态截图得出结论：长对话滚动性能、真实工具流与原生问答全链路、弱网切换、系统回收、相机实际识别和多设备并发。扫码 Activity 的 FLAG_SECURE 阻止 ADB 图片，不属于前端缺页。

本次后端补齐不会自动改变上述前端入口和交互状态。前端后续接入应以真实用户操作和业务闭环验收，不能仅按截图数量或文件数量宣称完成。
