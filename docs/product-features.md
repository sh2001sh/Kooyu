# 工作台功能完善设计

更新日期：2026-11-10。状态：功能验收设计。主要界面/API 已实现；逐项实现、已测、待验证与未实现见 [实现状态](implementation-status.md)，本文件的要求不代表完成声明。基于 [项目调研](research.md) 补齐可操作的产品行为；项目与主对话层级以 [会话模型](session-model.md) 为准。

首轮仍完整接入 [10 种 harness](harness-catalog.md)。下述增强共用 Session Host、原生适配器与 Kodo 工具，不增加固定工作流或多个管理 agent。

## 1. 首轮功能范围

| 功能 | 产品行为 | 参考依据 |
| --- | --- | --- |
| 统一会话中心 | 项目聚合、harness 筛选、置顶、归档、历史发现与搜索；支持未归属会话 | Codeg、Magpie |
| 待处理收件箱 | 聚合原生审批/输入请求、运行失败、预算/连续失败暂停；跳转到真实会话 | DeepSeek Superagent 的通知思想、bb 的共享事件 |
| 运行与托管时间线 | 显示消息来源、唤醒原因、续聊、暂停、交接、失联和恢复 | bb、CodexHost |
| 用户接管与停止 | 用户输入暂停自动续聊；取消本轮、暂停托管、停止运行是不同操作 | CodexHost 的 watch 边界、现有设计的 generation 校验 |
| Harness 健康与能力 | 安装、版本、登录、连接诊断；能力按版本显示真实支持情况 | Codeg、Harnss |
| 项目与工作位置 | 显示 cwd/host/分支/worktree，发现多个会话正在使用同一位置 | Orca、bb |
| 成果查看 | 文件改动、diff、测试输出、生成文件和来源链接 | Harnss、Craft、Codeg |
| 配置隔离与生效检查 | 多实例独立 绑定，显示实际生效配置修订与模型 | Magpie、CC Switch |
| 监控模式和运行限制 | 仅观察、通知、自动继续；用户可设预算、结束时间、续聊次数和连续失败阈值 | DeepSeek Superagent、CodexHost |
| 跨 harness 交接 | 选择材料后创建新的目标会话；保留来源与交接关系 | 基于统一会话模型提出的产品设计 |
| 用量与预算控制 | 执行成本、Kodo 成本、估算和实际账单分开；达到本地阈值暂停新的自动调用 | Magpie、CC Switch |
| 手机访问 | 访问相同会话和收件箱，发送消息、处理交互、停止和暂停托管 | bb、Codeg、Orca |

这是一份首轮实现范围，不代表参考项目中的同名能力已经在本产品可用。高级目录内容搜索、自动修复环境和完整 IDE 功能不作为上述能力的默认依赖。

## 2. 会话中心与历史搜索

导航提供全局主对话、待处理、全部会话、未归属与项目。harness、状态、托管者、host 是筛选维度；可保存常用视图。统一会话只有一份索引，切换视图不改变归属。

本地索引首先覆盖标题、可取得的消息文本、项目和 harness 元信息；SQLite FTS 足够，不先引入向量库或记忆 agent。用户可展开搜索工具输出。搜索结果带命中片段、来源会话和时间，点击定位原消息。

历史不可读取、尚未索引、来源离线分别显示；不能把未取得的历史说成“没有记录”。索引只读导入原生历史，可重建，不向外部会话文件追加产品状态。归档历史默认从普通列表隐藏，可通过筛选重新找到。

## 3. 待处理收件箱

每项包含会话/项目、harness、请求类型、发生时间与明确操作。以原生请求 ID 或稳定事件 ID 去重。桌面与手机操作同一请求；一端处理后另一端显示“已处理”，不能再次发送过期回应。

审批与需要用户回答的请求维持原生语义。运行失败可以打开错误详情或恢复操作；预算暂停可以调整限额或保持暂停；“标记已读”只改变阅读状态，不等于批准、重试或恢复执行。

普通回合结束默认进入活动记录。用户开启通知才触发提醒；相同目标的连续事件可合并通知，但保留逐项事实。通知服务不调用 Kodo。用户需要处理的交互不被普通完成通知淹没。

## 4. 时间线、接管与停止

正文用于消息与工具输出；侧栏时间线用于运行事实和管理行为。常见条目为“用户从手机发送”“主对话发起续聊”“等待输入”“连接中断”“恢复连接”“用户暂停托管”。每个自动输入可追溯到发起它的主对话和触发事件，底层 command ID 等仅在诊断详情中展开。

用户输入会先暂停目标的自动续聊，再按 native 能力发送、排队或 steer。UI 显示等待发送的消息及来源；尚未发送的用户消息可撤回。发送结果未知时先对账，不提供会造成重复执行的盲目重试按钮。

当前实现中，撤回只取消 accepted 的用户消息；dispatched/confirmed/unknown 不能假装撤回。本地删除要求空闲且没有在途/未知命令，撤销相关管理关系并从列表、正文查询和搜索移除；原生文件、原生身份与对账回执保留。单条已发消息删除、原生 rollback 和内容彻底擦除未实现。运行中 new 拒绝，queue 顺序等待，支持的 steer 直接进入当前原生回合。实测范围见 [消息操作复测](test-results-2026-11-11-fixes.md)。

| 操作 | 明确效果 |
| --- | --- |
| 取消本轮 | 请求原生 cancel；保留会话，显示取消是否确认。托管仍启用时操作旁明确说明可能后续继续 |
| 暂停托管 | 停止该关系后续自动发送；已经运行的原生任务继续，除非另选停止 |
| 停止并暂停托管 | 暂停目标自动续聊、使旧待办失效，再取消其运行 |
| 主对话批量停止 | 只作用于所列的、该主对话拥有自动控制权的目标 |
| 应用“停止全部” | 明确列出所有受管 host 的活动目标；逐一记录取消结果，失联目标保持“未确认”，不能显示全部已停 |

取消超时、原生后台子进程仍在运行和全部静止分别呈现。普通关闭窗口只断开 UI。默认的显著停止按钮使用“停止并暂停托管”，降低用户停止后自动重启的意外。

## 5. 监控模式与限制

| 模式 | Host 行为 | 模型调用 |
| --- | --- | --- |
| 仅观察 | 保存状态与事件，更新会话列表和时间线 | 无 |
| 通知我 | 观察并按条件向用户发送通知/收件箱事项 | 无 |
| 自动继续 | 对选定事件创建持久 wake，唤醒对应 Kodo 主对话 | 有；模型按需读取目标结果 |

off 与 paused 是关系未启用/暂停的状态。三种模式均不把目标回合结束当作用户目标完成。主对话可同时管理不同模式的目标，列表显示每个目标的实际模式。

用户可设置托管预算、结束时间、最大自动续聊次数和连续失败暂停阈值；未设置的限制不自动变成额外工作流。达到限制后暂停新的自动调用并产生一项待处理记录。结束时间默认停止新增自动调用；是否同时取消正在执行的回合，由用户在设置时选择并展示。

观察轮询不消耗续聊次数。自动输入只有在原生接受被确认后计数，结果未知期间保留一次待核对占用，不能通过自动重试耗尽次数或重复执行。审批等待、断线未知不计为已确认执行失败。

## 6. Harness 与配置面板

面板列出首轮 10 种 harness 的安装位置、版本、可用实例、认证状态和能力。未安装、未登录、版本不兼容、无法连接分别说明。检测过程不启动真实模型任务；连接检查分成不计费的协议检查与用户主动发起的最小模型请求，实际可用方式取决于 adapter。

绑定 可绑定到多个实例。页面显示“已配置”与“本轮实际生效”的区别；修改影响下一轮还是需要新实例由 adapter 明确提供。避免覆盖用户已有全局设置，凭据保存与展示遵循总体设计。

能力详情分别列出历史读取、原生恢复、外部活动会话观察、引导、取消、后台状态、usage 和 quota，并记录验证版本。安装成功或 ACP 握手成功不能自动勾选全部能力。

## 7. 工作位置与成果查看

项目可绑定多个 host/目录/worktree，当前会话始终显示实际位置。多个活动会话指向同一工作位置时，显示共享目录提示和会话链接；可选择新建 worktree。是否隔离由任务决定，产品不为每次聊天强制创建分支。

成果面板聚合适配器提供的改动、工具输出和已知产物。diff 保存比较基线；普通共享目录下无法可靠判断作者的变化标明“工作区改动”，不能全部归功于当前 harness。测试结果带来源运行与时间，输出存在不代表结论正确。

生成文件链接带 host 和真实路径；跨会话交接引用相同产物时保留来源。预览默认查看内容，不因为打开产物就执行生成的程序。文件修改、撤销或 Git 操作有明确动作入口，不由查看面板自动触发。

## 8. 跨 harness 交接

用户选择目标 harness、项目与工作位置后，预览可编辑的交接材料：目标、当前进展、相关文件、已执行检查、未完成项和来源消息链接。可以选用现有文本；需要生成摘要时才调用 Kodo，并记录该成本。

发送后创建新的原生 session，旧会话保留原 ID 和历史。交接记录关联两者；目标会话可能不支持源模型的附件/上下文类型，发送前据能力明确提示或转换为可读取引用。

交接默认不停止源会话、不转移托管控制权；界面分别提供这些选项。若用户选择替换正在执行的工作，先确认源停止状态，再启动目标，避免两端在同一目录重复修改。没有原生恢复能力的 harness 不能借交接功能宣称支持 resume。

## 9. 用量、预算与归属

用量按会话、项目、harness、绑定、模型和时间查询。执行费用归执行会话；项目主对话费用归项目；全局 Kodo 管理费用单列。主对话关联目标的总览仅引用这些记录，不能重复记账。

预算可设在项目、绑定 和托管关系上，发起自动调用时检查所有适用限制。多个并行调用需协调待计费用占用；无法预知最终 token 与供应商返回延迟，必须显示可能的超额边界，不能保证按最终账单金额精确截断。

实际金额、按价格修订估算的金额、本地预算和原生账户额度分别显示。未提供的类别保留未知。达到阈值后暂停新的自动调用，已有调用是否取消按明确设置执行；修改 绑定 不抹掉已发生的费用。

## 10. 远程执行 host 的独立扩展

首轮为本地独立 host + 手机客户端。设计同时保留 `hostId`，为后续连接家中常开电脑或服务器预留边界；这不改变首轮 10 种 harness 一起交付的要求。

多 host 扩展时，一个 host 管理自己的原生进程、凭据和持久日志。desktop 聚合会话视图；项目可关联多个远程工作位置。手机操作指定会话的所属 host，不将远程路径当成本地路径。

执行会话不会因 UI 切换 host 就迁移进程。迁移工作需要新建目标会话并明确准备文件/交接上下文。配置在远端是否可用由远端检查，不能仅复制本地凭据引用就声称绑定成功。

主对话本身也有运行 host。若需本机休眠后继续调度，Kodo 主对话及其 wake 服务必须运行在常开 host；只有执行端在远端时，它可以完成当前任务，但休眠中的本地 Kodo 无法继续调度。断网后保留事件和已接受的命令状态，重连对账，不自动在另一 host 重做结果未知的命令。

此扩展需要单独完成连接配对、远程生命周期、事件恢复和跨 host 交接的实现与验收；当前仅定义设计，不宣称已经支持。

## 11. 交付验收

会话输入框提供原生模型/思考强度设置，支持同一原生 ID 下在回合之间切换；运行中可先保存，下一普通回合应用，直接引导仍属于当前轮。原生目录、账号授权和 绑定 凭据分别表达，未知档位不猜测。待发消息支持编辑、撤回、立即发送；不支持原生插话时明确展示限制，用户可保留排队或撤回。桌面与手机使用同一设置/待发 API、修订和幂等回执，详见 [实现与验证矩阵](test-results-2026-11-11-models.md)。

首轮除 10 种 harness 的独立聊天契约外，验证搜索结果可定位、同一原生会话不重复导入、手机/桌面交互只处理一次、用户接管后旧自动消息失效、预算暂停不被迟到事件解除、交接不伪造原生恢复、共享目录的改动不错误归因，以及时间线可追溯自动输入来源。

会话层级的场景验收见 [会话模型](session-model.md)。这些为验收标准，当前已实现/已测/待验证与未实现的区别见 [实现状态](implementation-status.md)。
