# 配置、引擎安装和 Provider 工作流

2026-11-12。设置按通用、外观、引擎与安装、Provider、模型库、高级模型映射、新会话默认配置、个人指令组织。参考 Codex 的设置分类，但只提供 Kodo 已实现并持久化的功能，不加入无效的占位开关。参考：https://developers.openai.com/codex/app/settings/ 。

## 普通配置路径

1. 在 Provider 页填写名称、协议入口和凭据。保存后自动从各入口的模型接口导入模型，不再需要转到模型库逐个添加。获取失败时保留已保存 Provider 和原有模型，显示失败状态并允许重新获取。
2. 模型库自动合并模型接口元数据与 models.dev 目录。优先级为手工覆盖 > 当前入口 > 公共目录。窗口、输出、价格和能力保留来源；价格单位统一为 USD / 百万 Token。留空表示自动，价格 0 表示已确认免费，可恢复全部自动参数。
3. 展开引擎，选择 Provider 和兼容协议入口，保存用于新对话。此处不要求选择模型。固定模型和协议映射仍保留在高级模型映射页。
4. 新建或已有 Provider 会话在模型菜单中切换该配置内的模型。空闲会话切换后恢复同一个原生会话身份；运行中的选择在下一条普通消息生效，引导消息保留当前回合配置。
5. 引擎历史菜单可以切回原生登录/文件或之前保存的 Provider / 固定模型配置。本机原生文件不被重写。已创建会话固定 Provider、凭据和模型元数据修订；模型参数更新应用于后续新会话。

## 安装范围

Codex、Gemini CLI、OpenCode、Kimi Code 支持从引擎页安装/升级官方 npm 发行包。每次安装到新的独立目录，验证启动文件后才切换入口；失败继续使用原入口。可以恢复上一入口，也可以指定可执行文件和参数。安装操作仅允许本机 Host 请求，界面关闭后任务继续，Host 重启会把中断任务标记失败。

Kodo、pi 和 Claude Agent SDK 随应用升级；其他引擎提供官方安装说明和自定义启动入口。安装管理测试使用临时发行包验证切换、失败、目录穿越拒绝、冲突和恢复，不代表实际下载或真实模型对话已验证。

## Kodo 独立性

Kodo 的本机配置位于 Host 数据目录的 `kodo/`，其 settings/models/auth 和凭据缓存按此目录隔离；pi 继续使用 `PI_CODING_AGENT_DIR` 或 `~/.pi/agent`。两者共享 SDK 实现不等于共享用户配置。引擎默认 Provider 分别保存，选择相同的公共 Provider 是用户显式操作。

## 应用偏好

默认对话引擎、发送快捷键、模型元数据自动更新、主题、消息字号、减少动态效果和个人指令均写入本机数据库，并用修订号防止多窗口互相覆盖。个人指令在新会话创建时保存快照，只附带于首条普通消息；已有会话不随全局更改。
