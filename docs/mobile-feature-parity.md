## 对话渲染与桌面对齐

两端的对话解析逐项对应桌面 `TranscriptView.tsx` 的 `buildTranscriptRows`：文本增量与最终消息合并，思考按 itemId 分块，工具事件按 toolCallId 合并生命周期（开始/完成/退出码），子代理事件归入各自的嵌套记录，`turn-ended`/`settled` 失败只显示一次原因，连接断开显示为错误行。Android 实现在 `Transcript.kt`，iOS 在 `Transcript.swift`。

显示规则与桌面默认偏好相同：连续工具调用折叠为「N 次工具调用」组；运行中且最后一块是思考时显示「正在思考…」并自动展开；同一回合内第二段起的回答不再重复引擎抬头；工具输出超过 20,000 字符截断。用户消息中的文本附件拆成文件标签，点开查看内容。颜色取自桌面 `app.css` 的 `:root`/`.dark` 变量，引擎徽标取自 `HARNESS_VISUALS`。

阅读位置在底部时自动跟随流式输出，向上翻阅后停止跟随并显示「回到底部」按钮。运行中输入框为空时发送键变为停止键。

## 设备与连接行为

一台手机保存多台电脑，选择当前电脑后显示它的工作台。切换会立即清空旧数据；每个请求捕获电脑身份、token 和 generation，旧请求返回不会污染新电脑。保存列表按 hostId 去重，重新配对不丢失该电脑的待核对操作。移除本机连接不会停止电脑任务或代替 Host 侧撤销授权。

正常扫码、确认和列表只显示名称。手动输入是默认收起的排障入口；网络错误不输出连接 URL。来源编辑中的「模型 API 地址」是用户配置的模型服务入口，与电脑配对 URL 不同。

Android 的整本设备数据使用 Keystore AES-GCM；iOS 使用 ThisDeviceOnly Keychain。两端保留 HTTPS、系统证书校验、禁止跨地址重定向等约束。未知结果不自动重发；发送、停止、模型设置、待发编辑通过各自回执查询核对，其余非幂等操作由用户核对后清除本机标记。

会话轮询为前台 2 秒，用量为前台 10 秒；退入后台取消读取。应用内未实现所有电脑同时常驻轮询或推送。

## 与桌面共享的计算及写入规则

- 先从全部用量记录找出存在 turn 记录的会话，再移除相应累计 session 快照，最后进行日期/项目等筛选；不能先筛日期再去重。
- 费用未报告保持 unknown/null；实际费用、估算费用和已知费用余额独立展示。图表按本机当地日期分组。
- 使用 Host 的严格创建 schema，创建会话不传发送用的 requestId；继承绑定与显式原生 null 区分。
- 会话权限单独 PATCH，模型设置使用 expectedRevision；编辑来源/模型/绑定及默认配置保留修订检查，避免覆盖桌面并发修改。
- 创建成功但首条消息失败后打开已创建会话并保留草稿，不再次创建会话。
- 文本附件与桌面使用相同文件标记，检查 UTF-8、文件数和字节限制。
- 原生问答保留各协议的 question ID、选项 ID、多选/其他/跳过含义；不把未知问题当成普通批准请求。

## 保留在电脑本机的操作

Host 明确限制的首次引导、引擎安装/升级/登录、系统入口修改和设备授权撤销仍在运行 Host 的电脑操作。移动端不绕过这些限制；因此本版不宣称所有桌面操作均能远程完成。

## Android 真机验收

1. 安装 release/android/Kooyu-0.2.0-debug.apk；已有同签名版本时覆盖安装，检查旧电脑连接和历史仍可读取。桌面 Host 使用本次源码构建，保持电脑在线并启用手机连接。
2. 从「设置 → 电脑」添加第二台电脑并扫码，分别设置容易识别的名称。确认扫码确认页、设备列表和切换菜单只显示名称；手动地址输入保持默认收起。
3. 在两台电脑间来回切换，核对会话、项目、用量属于当前电脑；给一台电脑断网后，检查另一台仍可单独连接。存在结果不明的写入时，先核对原电脑结果，不自动重复提交。
4. 新建带项目、目录、模型和首条消息的对话，检查桌面同步出现；继续测试发送/停止、历史搜索、分页、重命名、归档恢复、待发编辑及审批。离开应用再返回，检查刷新恢复且没有重复创建。
5. 打开用量，使用相同时间/项目/引擎/口径与桌面比较 Token、缓存、已知费用及预算；未上报费用保持未知。检查移动端保存预算、模型绑定、默认配置后桌面同步；同时修改默认配置应提示冲突。
6. 检查小屏、横屏、平板、深色外观、大字体、启动图标，以及相机权限拒绝/恢复、扫码取消、后台恢复、网络切换。记录手机型号、Android 版本、Host 版本和复现步骤，以上是待执行的设备验收项。
