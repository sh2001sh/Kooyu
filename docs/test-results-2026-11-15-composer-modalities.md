# 输入框、消息操作与模型输入模态验收

日期：2026-11-15。

## 实现范围

- Android、iOS 对话输入框接入模型、思考强度、工具权限、托管附件、发送与取消当前回合。运行时消息使用排队或引擎声明支持的 steer；空闲发送新回合。新建对话支持附件及首发失败后保留文本、附件草稿。
- 桌面和移动端的用户消息增加时间、复制及编辑入口，助手消息增加“更多 → 分支到新聊天”。编辑创建新聊天草稿，由用户决定何时发送。
- 分支复制选定位置之前的用户和助手文本、附件上下文，保留源模型绑定修订；不会修改原会话或复制选定位置之后的消息。它是新的会话及上下文副本，不是各 SDK 原生日志的原地修改或原生 fork。超过 1000 条消息、160000 字或 10 个附件时明确拒绝，避免静默截断。

## models.dev 自动识别与手工覆盖

使用现有公共目录 `https://models.dev/catalog.json`，解析目录的 `input` / `modalities.input`。配置页每个模型可选择“自动”“仅文本”“文本与图片”，显示自动识别结果及当前生效能力。手工配置持久保存，选择自动移除该覆盖；不展示冗长的聚合目录来源链接。

来源模型继续使用既有的端点发现值、目录值及手工覆盖合并规则。绑定生成新修订，已存在会话继续使用冻结的绑定修订，不会静默更改运行中的路由。

pi / Kooyu 原生运行时的补齐顺序：

1. 同模型 ID、同 API 协议、同完整 Base URL 的唯一已保存模型手工输入模态。
2. 原生配置明确声明的输入模态。
3. 唯一匹配路由已解析的输入模态。
4. 同模型 ID 的目录记录，优先匹配原生 provider。

未匹配到能力时保持未知，不通过模型名中含“vision”等字样猜测。当前运行时输入能力字段支持文本与图片；本次不宣称新增音频、视频等原生输入协议。聚合商同名模型可能提供不同能力，手工覆盖用于校正实际入口；本地声明不能使上游接口获得原本不支持的能力。

## pi 图片与思考档位

本机 `.pi/agent/models.json` 中 `codegoai/deepseek-v4.1-flash` 缺少 `input`，pi SDK 默认把它当作纯文本。已仅给此条目补 `input: ["text", "image"]`，保留其他配置；此修改位于用户目录，仓库 diff 不包含它。同时修复绑定模型使用 `provider/model` ID 时的模型查找和图片能力检查。

显式思考档位设置后核对 SDK 的实际档位，不一致则拒绝发送；从显式档位切回默认时恢复默认设置，避免沿用之前的 max。发送状态记录 `effectiveModel`、`effectiveReasoning`、`settingsRevision`。

已有本地会话记录不足以证明用户描述的那次请求实际携带 max：检查到的两条 pi 会话发送设置为 null。max 是推理强度而非最低思考文字长度，不能只凭展示的思考长短判断是否应用。现有协议测试证明 DeepSeek Responses 的 none/low/high/max 序列化至 `reasoning.effort`；SDK 测试证明实际档位和图片参数传入。没有向真实收费模型发起验证请求。

用户明确授权本次启动后，先将生产数据库在线备份至 `.local/preview/backups/composer-modalities-20261115/kodo.sqlite`，然后以原数据目录 `.local/preview` 启动 4330 Host。

最终运行 PID 为 33008；`/api/health`、页面 `/`、`/api/provider-configuration` 均成功。`/branch` 对缺失参数返回预期的 400，证明路由已加载且未创建测试分支。现有未绑定 pi 会话 `/settings?refresh=1` 返回 200，运行时精确模型 `codegoai/deepseek-v4.1-flash` 报告 `input: ["text", "image"]`。最后 8 个会话均 idle。4357 的独立视觉测试 Host（PID 46292）保留。

生产配置中的两个已保存 DeepSeek 模型仍自动匹配到目录的 zerogpu 同名文本记录，没有擅自改变其手工配置或已冻结会话绑定。用户可在模型来源编辑中将该实际入口覆盖为“文本与图片”；更新后的模型绑定用于新会话，已有冻结绑定不会被目录刷新改写。
