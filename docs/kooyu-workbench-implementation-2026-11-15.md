# Kooyu 跨端工作台优化：实现与验收

日期：2026-11-15。实施依据：[Marvis 结构与 Granola 风格参考方案](kooyu-marvis-structure-granola-style-2026-11-15.md)。

本轮落地对话、项目、工作、成果及验收之间的主要链路，保留 Kooyu 日落珊瑚品牌和原有深浅主题。Android 继续使用「对话 / 用量 / 模型来源 / 设置」，项目留在对话首页，收件箱继续位于右上角。

## 1. 本轮实现

| 区域 | 桌面 React | Android Compose | iOS SwiftUI |
| --- | --- | --- | --- |
| 工作聚合 | 侧栏固定入口、项目就近入口、会话成果入口 | 首页、项目和会话入口，完整原生页面 | 对应入口与原生页面，源码实现 |
| 工作记录 | 目标、待处理询问/审批、普通运行会话、搜索、需要我处理筛选 | 同一数据与状态口径 | 同一聚合接口 |
| 成果 | 项目筛选、文件信息、版本、验证状态、预览/下载、来源会话 | 原生文本/图片预览、保存、打开、分享、来源会话 | 下载校验、Quick Look、系统分享 |
| 自动计划 | 列表、名称/内容/时区/触发规则/次数/预算编辑、预览、启用、暂停、手动运行、运行记录 | 原生列表和详情，支持相同管理动作 | 对应原生表单与动作 |
| 项目概览 | 目录、最近对话、就近新建 | 同一项目上下文 | 同一项目上下文 |
| 项目约定 | 查看作用范围、创建、编辑、确认、删除 | 原生管理与修订检查 | 原生管理与修订检查 |
| 执行能力 | 实际引擎安装状态与声明能力，未知单独标示 | 仅展示已确认支持的动作，显示实际安装状态 | 相同口径 |
| 常用任务 | 四个内置模板填入可编辑草稿 | 同一模板，不自动发送 | 同一模板，不自动发送 |

界面复用现有主题角色，采用轻量列表、统一间距、较少分隔表面和珊瑚色选中态。手机配置项和发送按钮扩大触摸区域；工作列表采用适合手机阅读的字号。桌面宽屏可显示成果或工作检查器，窄屏改为纵向承载，移动端使用原生完整页面。

项目授权、托管和计划创建继续以主对话为主动入口。工作台承接查看与管理，不新增项目授权配置步骤。

## 2. 后端补齐

- 新增只读 `GET /api/workbench?projectId=<uuid>`，集中返回项目、会话、工作目标、成果可用性、计划与运行记录、约定、待处理事项和实际执行能力。读取不启动或恢复模型。
- 项目参数格式不正确返回 400，项目不存在返回 404；删除会话不会通过旧目标或文件记录重新出现。
- 成果在 SQL 查询阶段限定项目，再应用最近 500 项上限，避免其它项目的大量成果挤掉当前项目。每项保留文件、目标与会话来源；文件失效时仍可说明原因。
- 计划保存/暂停/执行、约定创建/更新、目标验收纳入客户端操作回执。稳定请求 ID、防重复执行、修订检查及 `pending/unknown` 核对保持一致。
- 直接执行计划的 API 同样检查 `automations.run`，尊重 Host 的冻结状态。
- 修正原生目标验收请求，统一使用 `/goals/:id/review`、`decision` 和 `expectedRevision`，成功后才关闭详情。

最近计划运行记录上限为 200 条；这是当前聚合接口的窗口，不表示只有这些历史。更早数据仍需进入所属目标/业务详情查看。

## 3. 文件与恢复边界

Android 和 iOS 使用配对认证读取成果，单次最多 32 MiB，并验证 SHA-256。Android 文本预览显示前 128 KiB，保存可以获得完整文件；图片解码采用采样，系统保存和分享使用本机副本，不将访问令牌放进外部链接。

草稿只保存在当前设备，按电脑和会话隔离，不宣称跨设备同步。Android 使用已有 Keystore 加密能力，iOS 使用文件保护；桌面使用当前来源下的本机存储。阅读位置在当前运行期间恢复，不承诺重启应用后的历史锚点恢复。

结果未知的管理操作不会自动重发。详情页可以查询回执；只有用户已核对业务对象后，才能手动清除本机阻塞标记。重连提示基于实际未处理事项数量。

## 7. 未纳入本轮完成声明的扩展

参考方案中的自定义模板收藏库、跨重启保存全部筛选偏好、离线期间逐项变化摘要，仍属于后续增强。本轮提供四个内置模板、当前视图筛选、本机草稿/阅读恢复及重连待处理数量提示。没有增加技能商店、虚构执行者或手机本地 harness。

iOS 的实际编译和运行、实体手机/平板与后台切网、桌面安装包的系统集成，需要在对应环境继续验收，不能用截图或 Swift 语法检查替代。
