## 设计定位

主张：**让工作，接着向前。**

品类：本地 AI 会话工作台。围绕项目组织不同原生工具的会话，保留工具身份；直接聊天与用户显式开启的 Kodo 托管是不同模式。Kodo 产品主 agent 与独立 pi harness 保持区分。手机是同一 Host 的客户端，不宣称手机本地执行或电脑休眠后仍能继续调度。

视觉上，官网以品牌姿态和清楚的产品故事吸引注意，软件内则让位于会话、状态和操作。珊瑚色用于识别和重点动作，暖白 / 深墨承载长时间使用的阅读层级；不把装饰性大标志放入工作内容中。

## 文件性质与生成来源

这些是模型生成的设计概念图，可用于审阅、后续设计细化和界面实现参考。它们不是运行截图，也不代表已实现、已发布或已通过功能验收。图中的 Atlas 项目、会话、消息、活动均为明确标注的设计示例。

模型生成的细小图标和文字可能仍有细节误差，实施时应采用真实产品字段和正确的原生工具标识。正式 Kodo 标志应取自 [标识素材目录](../assets/README.md)，而不是从设计图中截图取用。

英文字标已另行修订为推荐版 B「微倾流线」，见 [字标对照](../wordmark-studies/README.md)。本目录六张概念图保留生成时的原字样，未随此次修订重新生图；后续实现以最新 SVG 字标和横版组合为准。

生成分两步：产品定位、浅色桌面、品牌应用以用户选定的珊瑚标志作参考；官网、深色桌面和手机端同时参考该标志与浅色桌面图，以保持一致。官网另做一次局部修订，以区分 Kodo 与 Codex 的标识，并收敛功能文案。

每张图的提示词在 `prompts/` 中，实际发送的完整文本以 `.request.txt` 结尾；官网修订提示词单独保存。模型、参考图 hash、尺寸等记录在同名 JSON 中，PNG 元数据也嵌入了模型和提示词。

本轮没有更新应用源码或上线官网。后续实现需要将概念图转为真实组件、响应式布局和可访问交互。
